## Текущий дефект

**P2 — `journal read -s all` теряет scope и успешно возвращает весь журнал.**

**Пути:** `src/cli/app-command.ts:31`, `src/app/execute-command.ts:44`.

Перевод CLI использует одну строку `'all'` для двух разных входов: `--all` и `--scope all`. Диспетчер безусловно трактует её как весь журнал. До рефакторинга `-s all` разрешался через реестр как организация `all`; без такой организации возвращалась ошибка.

**Repro на временной установке, статически прослеженный, не запускал:**
```sh
mypi bootstrap
mypi project add all/project --code AP
mypi journal add org-only -s all
mypi journal add global-only
mypi journal read -s all
```
Ожидается только `org-only`; теперь возвращается также `global-only` и другая история вне организации.

Это регрессия CLI и фильтрации, не обход ACL: scope здесь не является авторизацией. Нужно различить явный `--all` и строковую ссылку на организацию до общего dispatch. Добавить независимые проверки: `-s all` ограничивает организацией, `--all` читает всё, неизвестная организация отклоняется.
