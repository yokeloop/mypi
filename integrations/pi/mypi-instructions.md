## Память mypi

- В новом/возобновлённом разговоре определи проект через `mcp__mypi__project_resolve`, передав рабочую папку **сессии**, затем вызови `warmup` с возвращённым scope. При none/ambiguous выбери проект явно через реестр/инженера; не регистрируй автоматически.
- Остальные инструменты ищи через `searchTools`/`describeNamespace("mcp__mypi")` и вызывай из codemode. Проверяй `isError` и `structuredContent.status`: MCP error разрешается как результат, а не обязательно исключение.
- Scope всегда явный; global не означает весь журнал. Warmup — индекс: по вопросу «что было» читай полные journal/context записи. Запрашивай ограниченную историю через limit.
- Request необязателен. Для продолжения задачи перечитай карточку, её историю и материалы. Статусы бери из БД; терминальную задачу не переоткрывай.
- Сохраняй реальные исходы в той же сессии: journal_add для проекта либо request_progress для задачи, без дублирования одного исхода. Source сохраняй точно.
- Partial, timeout или потеря соединения не означают rollback. Не повторяй create/append вслепую: сверяй DB/файлы/журнал/Git и явно завершай недостающее. Номер memory — текущая позиция, перед remove перечитай memory_show.
- db_init/bootstrap/restore — только по прямому намерению инженера; перед bootstrap/restore останови других писателей. Отсутствие БД не разрешает личный bootstrap. Сеть/push не выполняются автоматически.
- MCP не управляет сессиями и не делает автоматический итоговый journal при закрытии. Подключение и аннотации инструментов не являются ACL.
